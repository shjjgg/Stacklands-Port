# 13 · 仓库结构与版本管理

## 1. 目标仓库布局（Unity 工程根 = 仓库根）

```
.
├── Assets/
│   ├── Scenes/                  IntroScene.unity, SampleScene.unity
│   ├── Scripts/                 GameScripts 反编译回填源码 (按内嵌源路径还原)
│   ├── Plugins/
│   │   ├── Managed/             ShapesRuntime/SokLoc/SokSheet/Sirenix/DOTween/Newtonsoft...
│   │   ├── PlatformStubs/       本目录桩接层 (IPlatformServices/SteamPlatformStub/...)
│   │   └── link.xml             IL2CPP 裁剪保留清单
│   ├── Resources/               cards/, boosters/, 配置/字符集/存档模板 TextAsset
│   ├── Art/                     贴图/图集/Sprite/音频/网格/字体 (导出资源)
│   ├── Shaders/                 保真链产出的 ShaderLab + HLSL
│   ├── DLC/                     cities_dlc, spirits_dlc (UnityFS, 原样; 不入库见 §3)
│   └── Editor/PortBuild.cs     构建入口
├── Packages/                    manifest.json (同版本依赖)
├── ProjectSettings/             2022.3.4f1 工程设置
├── docs/                        01–15 方案/盘点/待办文档与台账总览
├── tools/                       扫描/还原/提取/盘点脚本
├── ci/                          GitHub Actions 工作流
├── shader_extract/              shader 台账 (md/json 入库; blobs/ 不入库)
├── content_inventory/           配置/DLC/音频台账 (md/json)
├── *_inventory/                 类型/方法/字段/属性事件/特性/依赖/接口成员台账
└── .gitignore
```

## 2. 入库 vs 不入库

| 类别 | 内容 | 是否入库 |
|---|---|---|
| 工程源码 | 回填 C#、Editor 脚本、桩接层、ShaderLab/HLSL | ✅ 入库 |
| 配置/文档 | docs、tools、ci、`Assets/Plugins/link.xml`、台账 md/json | ✅ 入库 |
| 导出资源 | 贴图/图集/音频/网格/字体/Prefab/场景（AssetRipper 产物） | ✅ 入库（工程重建后） |
| 原始游戏数据 | `.assets/.resS/.resource`、DLC bundle、原始 DLL | ❌ 不入库（版权），本地/CI artifact 注入 |
| 派生 blob | `shader_extract/blobs/` | ❌ 由脚本重新生成 |
| 构建产物 | APK/AAB、symbols.zip、global-metadata.dat | ❌ 走 CI 构件归档 |
| 密钥 | keystore、密码、Unity 授权 | ❌ 走 GitHub Secrets |

## 3. 原始数据注入方式

- 本地开发：将还原后的 `Stacklands_Data` 与 DLC bundle 放在仓库外受保护目录，脚本通过 `SOURCE_DATA / SOURCE_RAW / DECOMPILED_SRC` 指向。
- CI：原始数据作为私有 artifact 在 job 开始时下载到对应路径；不进 git、不进公开日志。
- 重新生成派生台账：
  - `tools/reconstruct_source.py` 还原分卷/侧车；
  - `tools/scan_static.py` 元数据扫描；
  - `tools/extract_shader_blobs.py` shader blob/台账；
  - `tools/export_content_inventory.py` 内容盘点。

## 4. 分支与迭代策略

| 分支 | 用途 |
|---|---|
| `main` | 可出包的稳定快照 |
| `develop` | 集成分支，日常合并 |
| `feature/<模块>` | 脚本回填 / shader / 平台桩 / 资源修复 等专项 |
| `release/<版本>` | 出包前回归，挂冒烟清单结果 |

- 每个专项分支合并前：静态分析 job 通过；P0/P1 冒烟用例记录在案。
- 提交信息按模块前缀：`scripts:` / `shader:` / `assets:` / `stub:` / `ci:` / `docs:`。

## 5. 版本对齐约束

- 工程 `ProjectSettings/ProjectVersion.txt` 必须为 `2022.3.4f1`，禁止升级编辑器版本。
- 第三方托管依赖版本以原版 `Managed` 引用为准；升级需记录兼容性核对。
- DLC bundle 与主工程同版本（2022.3.4f1），替换 bundle 时校验头版本字符串。

## 6. 大文件与体积控制

- 入库资源仅保留工程引用所需；原始高分图/音频在满足画质前提下按原版格式保留，不二次压缩失真。
- 台账 JSON/MD 入库；二进制 blob、构建产物不入库。
- 若资源总量超出 git 上限，评估 Git LFS 存放 Art/ 资源目录；原始游戏数据仍走外部 artifact。

## 7. 交付物快照（当前 PORT 目录）

- 文档：`docs/01`–`docs/13` + `scan_report` / `shader_ledger` / `content_inventory`。
- 脚本：`tools/` 下 5 个 Python 工具。
- 工程胶水：`Assets/Editor/PortBuild.cs`、`Assets/Plugins/PlatformStubs/`、`Assets/Plugins/link.xml`。
- CI：`ci/unity-android-il2cpp.yml`。
