# 02 · 移植主方案（一比一复刻）

## 0. 不可动摇原则

1. **引擎版本锁定 2022.3.4f1**：编辑器、GameCI `unityVersion`、Android module、IL2CPP 工具链全部对齐该版本；不跨 LTS 大版本，不升级补丁号以外的版本。
2. **保留原版引用链**：场景、Prefab、Animator、Timeline、脚本事件、本地化、材质绑定、Sprite 图集、AudioClip 引用按原样保留；不擅自删减、不重排资源路径。
3. **不改原版逻辑**：反编译回填的 C# 仅做“可在 IL2CPP/Android 编译运行”的最小适配；玩法规则、数值、事件顺序以原版为准。平台差异通过**隔离层/桩接**解决，不在游戏逻辑内散落 `#if`。
4. **资源不替换**：贴图、音频、字体、模型、Shader 资产沿用原版导出物；确需转换（压缩格式）时保留原资产副本并记录映射。

## 1. 总体路线

```
PC Mono 原版数据
   │  (还原 .assets/.resS/.resource 分卷, 补齐侧车)
   ▼
AssetRipper 导出 Unity 2022.3.4f1 工程 (资源 + 场景/Prefab + MonoScript 桩 + C# 反编译)
   │
   ├─ 第三方托管 DLL 接入 (ShapesRuntime/SokLoc/SokSheet/Sirenix/DOTween/Newtonsoft/TMP/PostProcessing...)
   ├─ 平台隔离层: Steamworks / ImGui 覆盖层 / Google Sheets / 补丁子系统 桩接
   ├─ 资源引用链修复 (断引用/丢贴图/空脚本/动画绑定/变体)
   ├─ Shader 保真链 (见 03)
   ▼
IL2CPP Android 工程 (arm64-v8a, 主; armeabi-v7a 按需)
   │
   ▼
GitHub Actions + GameCI 出包 → 设备冒烟 (见 07) → 迭代修复
```

## 3. P0 源包还原细则

自动化脚本：`tools/reconstruct_source.py`（分卷拼接、侧车归位、版本/大小校验，已在本批源包上跑通，0 告警）。

1. 分卷资源 `sharedassets1.resource` 按 `z01 → z02 → .zip` 顺序拼接解压（已验证解压出 131,903,232 字节，与清单一致）。
2. 将上传侧车归位到 `Stacklands_Data/`：
   - `resources.assets.resS`、`sharedassets0.assets.resS`、`sharedassets1.assets.resS`
   - `sharedassets1.assets`、`sharedassets1.resource`
3. 校验每个 `.assets` 头版本字符串为 `2022.3.4f1`；校验 `.resS`/`.resource` 大小与压缩清单一致。
4. DLC：`Cities_DLC`、`Spirits_DLC` 为 **UnityFS bundle**（头 `UnityFS`，5.x，2022.3.4f1），原样保留，不拆包进主工程。

## 4. P1 工程重建要点

- 用与 2022.3.4f1 匹配的 AssetRipper 版本打开还原后的 `Stacklands_Data` 目录导出工程；导出后核对：
  - 场景：`Assets/Scenes/SampleScene.unity`、`Assets/SokpopIntro/IntroScene.unity`
  - 资源路径：`cards/main_cards/...`、`boosters/main_boosters/...`（Resources 加载路径，**保持相对路径不变**）
- AssetRipper 反编译的 C# 作为回填起点；其自带 shader 反编译**仅作参考**，不直接采信（见 03）。
- 工程内按原版内嵌源路径还原目录结构（`Assets/Scripts/...`、`Assets/Plugins/...`），便于脚本引用与后续 diff。

## 5. P2 脚本回填与第三方接入

### 5.1 回填顺序

1. 引擎模块（InputSystem/Timeline/TMP/PostProcessing/Navigation/UI）由同版本工程提供，不手动搬运 DLL。
2. 游戏逻辑：GameScripts、Assembly-CSharp、firstpass、csS 反编译源码入工程。
3. 第三方托管：ShapesRuntime、SokLoc、SokSheet、Sirenix 序列化、DOTween、Newtonsoft.Json 以源码或官方预编译 DLL 接入；版本需与原版引用兼容。
4. 平台包装层：Steamworks.NET、UImGui/ImGui.NET、Google.Apis 按 05 文档桩接。

### 5.2 脚本引用核对

- 以 `scan_report.json` 的 `scripts_by_assembly` 为基线，逐程序集确认类齐全。
- 2372 个 TypeTree 缺失不可读的 MonoBehaviour，导出工程后在编辑器内查看 `m_Script`，区分“测试/编辑器残留（剔除）”与“真实运行组件（补回脚本）”；UnityPy 侧 35 个 PPtr 二次读取异常已定性为跨文件读取假象，可读对象内无真实断引用。
- `UnityEngine.TestRunner`(110)、`ShapesEditor`(1) 不进入 Player 构建。

## 6. 资源引用链保留规则（对应基线硬性规则①）

- **Animator / AnimationClip**：保留原 AnimatorController、状态机、参数、Avatar、动画事件；不重命名状态与参数。
- **Timeline**：保留 Director 轨道、绑定标记、信号槽与脚本事件调用。
- **脚本事件**：UnityEvent、消息订阅、`RuntimeInitializeOnLoad` 入口（Sirenix 初始化、InputSystem 初始化）按原样保留；被禁用子系统的入口需显式摘掉并记录。
- **本地化**：SokLoc 字典、CharSet、CJK 字体、TMP 字体资产与材质整条保留；不删任何语言。
- **材质绑定**：Material→Shader→贴图/参数引用保持原序；Shader 替换后需回填原属性名与默认值。
- **DLC/Resources**：`Resources/` 下 cards/boosters 路径字符串与 `CodeReferencedCards` TextAsset 保持一致。
